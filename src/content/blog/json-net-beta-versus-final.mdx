Some [Json.NET](http://www.newtonsoft.com/json) users have asked me whether it is ok to use Json.NET while it is in beta, or have asked if the a final version will be released soon because they need a recently added feature and their employer has a policy against beta software.
  
For Json.NET the only difference between beta and final is completed documentation.
  
Json.NET’s testing is completely automated. Approaching 400 unit tests and 90% code coverage (not 100% but [good enough](/archive/2008/06/14/unit-test-code-coverage-what-is-a-good-number)) they are the beginning and the end of Json.NET’s test policy. A final release is no different to beta or even a regular source code check-in when it comes to stability.
  
I think [one regression](http://json.codeplex.com/Release/ProjectReleases.aspx?ReleaseId=6987) over 3 years and many releases is doing pretty well 😊
